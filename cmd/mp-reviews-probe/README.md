# mp-reviews-probe — пробник кабинетов WB и Ozon

Записывает, **какие запросы отправляет кабинет** продавца, пока вы сами работаете в нём: жалоба на
отзыв, ответ, статусы жалоб, проверка открытого кабинета. По этим записям пишутся адаптеры браузерного
агента (этап 3). Пробник **ничего не делает в кабинете сам** — не кликает, не заполняет и не отправляет.
Все действия выполняете вы, руками, как обычно.

## Что нужно

- Windows 10/11 с установленным Google Chrome (или Linux с Chrome/Chromium).
- `mp-reviews-probe.exe` — сборка: `GOOS=windows GOARCH=amd64 go build ./cmd/mp-reviews-probe`
  (или `make build-windows`, результат в `bin/windows-amd64/`).
- Если Chrome установлен не в стандартное место — путь в флаге `-chrome` или в переменной
  `MP_REVIEWS_CHROME_PATH`.

## Запуск

```
mp-reviews-probe.exe -profile wb-ms -url https://seller.wildberries.ru/
mp-reviews-probe.exe -profile oz-ms -url https://seller.ozon.ru/
```

| Флаг | Что задаёт |
|---|---|
| `-profile` | имя профиля кабинета (обязательно): строчные латинские буквы, цифры, `-`, `_`. Один профиль — один кабинет. |
| `-url` | что открыть при запуске (необязательно — можно ввести адрес в Chrome самому) |
| `-out` | куда положить zip (по умолчанию — текущий каталог) |
| `-chrome` | путь к `chrome.exe` |
| `-v` | подробный журнал в консоль |

Профиль Chrome хранится в `%LOCALAPPDATA%\mp-reviews\chrome-profiles\<профиль>` — **тот же каталог
будет у браузерного агента**, поэтому в кабинет достаточно войти один раз (при первом запуске пробника).
Chrome открывается обычным видимым окном. Если Chrome с этим профилем уже открыт, пробник попросит его
закрыть: один профиль может использовать только один Chrome.

В консоли:

- **название шага + Enter** — отметка шага: сохраняются снимок страницы (`marks/NN-<шаг>.html`) и
  скриншот (`marks/NN-<шаг>.png`) текущей вкладки. Отмечайте шаг **после** того, как на экране
  появилось то, что нужно запомнить (открыт диалог, выбрано основание, пришёл ответ);
- **`q` + Enter** (или закрыть Chrome, или Ctrl+C) — завершить. Пробник соберёт zip и закроет Chrome.

Результат — `probe-<профиль>-<дата-время>.zip` с `events.jsonl` (всё по времени), `marks/` и
`summary.md` (таблица запросов и хронология: какой запрос последовал за каким действием и отметкой).

## Что записывается и что вычищается

Записываются запросы страниц кабинета (XHR/fetch и навигации) — метод, адрес, заголовки, тело, статус,
тело ответа; переходы между страницами, новые вкладки, iframe; краткий журнал ваших действий (клик,
начало ввода, изменение поля, отправка формы) — **без значений полей**, только длина текста (для
паролей и секретных полей — ничего). Запоминается текст выбранного пункта в выпадающем списке
(это основание жалобы).

Значения `Cookie`, `Set-Cookie`, `Authorization` и любых заголовков, параметров адреса, полей форм и
ключей JSON, в имени которых есть `token`, `auth`, `session`, `secret`, `sign` (а также `cookie`,
`csrf`, `passw`, `jwt`, `api-key`, `wb-seller-lk`), заменяются на `<скрыто>`; имена сохраняются.
JWT и `Bearer …` скрываются в любом месте. Из снимков страниц удаляется содержимое скриптов.

**Тела запросов и ответов сохраняются** — в них персональные данные покупателей (имена, тексты
отзывов). Файл результата остаётся у нас и **никуда не публикуется**. Скриншоты не вычищаются.
Перед тем как передавать запись разработчику, пролистайте `summary.md` и поищите в `events.jsonl`
куски своих cookie/токенов — если что-то осталось, сообщите: значит, у площадки заголовок с другим именем.

## Чек-лист

Действия настоящие и **необратимые** (жалоба на отзыв подаётся один раз). Для записи жалобы и ответа
берите отзывы, по которым их **и так нужно сделать**. Пока работает старая система жалоб WB, не
подавайте жалобы на отзывы, которые она может взять сама.

Отмечайте каждый пункт шагом в консоли, например `1 список отзывов`, `2 диалог жалобы`,
`2 основание выбрано`, `2 жалоба отправлена`.

### Wildberries (`-profile wb-<кабинет>`)

1. **Список отзывов.** Откройте раздел отзывов, найдите конкретный отзыв (поиск/фильтр, прокрутка,
   следующая страница). Отметка — когда отзыв виден.
2. **Жалоба на отзыв.** Нажмите «Пожаловаться» → дождитесь диалога (отметка) → выберите основание
   (отметка) → введите текст → при возможности приложите изображение → отправьте. Отметка — после
   ответа кабинета (сообщение об успехе или ошибке).
3. **Статусы жалоб.** Откройте место, где видны статусы поданных жалоб (в очереди, на рассмотрении,
   одобрена, отклонена); если есть фильтр по статусу — переключите его. Отметка.
4. **Ответ на отзыв** (по желанию): напишите и отправьте ответ. Отметка после ответа кабинета.
5. **Какой кабинет открыт.** Откройте меню выбора кабинета/организации, при нескольких кабинетах
   переключитесь на другой и обратно. Отметка на каждом шаге — по записи будет видно, какой запрос
   и какое поле ответа показывают текущий кабинет.
6. **Если встретятся**: ответы 403/498, капча, требование повторного входа — ничего не делайте
   специально, просто отметьте шаг (`6 капча`, `6 повторный вход`) и пройдите их как обычно.

### Ozon (`-profile oz-<кабинет>`)

1. **Список отзывов.** Раздел «Отзывы», найдите конкретный отзыв (поиск, фильтры, следующая
   страница). Отметка.
2. **Жалоба на отзыв.** Кнопка жалобы → диалог (отметка) → основание (отметка; важно увидеть **весь
   список оснований**) → текст → изображение, если форма позволяет → отправка. Отметка после ответа.
3. **Статусы жалоб.** Где видно, что жалоба подана и чем закончилась. Отметка.
4. **Ответ на отзыв — обязательно** для Ozon: напишите и отправьте ответ, отметка после ответа кабинета.
5. **Какой кабинет открыт.** Переключатель компании/кабинета: откройте, переключитесь и вернитесь.
   Отметки на каждом шаге.
6. **Если встретятся**: 403/498, капча, повторный вход — отметьте шаг и пройдите как обычно.

После записи отправьте zip разработчику **лично** (не в общий чат и не в репозиторий).
